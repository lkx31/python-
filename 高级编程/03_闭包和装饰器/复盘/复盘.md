## 二、今日核心知识点总结

### 1. 变量作用域【复习】
- 全局变量（函数外定义）/ 局部变量（函数内定义）
- 局部作用域**能读**全局变量；全局作用域**不能读**局部变量 —— 因为函数执行完，内部变量被垃圾回收机制（gc）回收
- `global` 关键字：在函数内声明要操作的是全局变量（Day06 老知识，今天对比复习）

### 2. 闭包【掌握】
- **三步走（缺一不可）**：① 有嵌套（外部函数套内部函数）② 有引用（内部函数使用外部函数的变量）③ 有返回（外部函数返回内部函数）
- 语法：`return inner`（返回的是函数**地址**，不是 `inner()` 的执行结果）
- 作用：正常 outer() 执行完局部变量会被 gc 回收；闭包让内部函数"抓住"外部变量 → 变量**延迟销毁**，可在全局作用域间接访问局部变量
- 代价：外部变量不释放 → **占内存**，别滥用

### 3. 修改闭包外层变量【易错】
- 错误版：内部函数里 `num = 20` 是**新建局部变量**，外层 num 不变
- 正确版：`nonlocal num` 声明后赋值，才真正改外层局部变量
- 对比：`global` 改全局变量；`nonlocal` 改外层（非全局）局部变量

### 4. 闭包案例：累加器【实操】
- `f = func()` 拿到 inner；`f(1)` 输出 1、`f(2)` 输出 3 —— result 在多次调用间**保留**（这就是"变量没被回收"的直接体现）

### 5. 装饰器入门【掌握】
- 定义：**不改变原函数源代码和调用方式**，给函数增加额外功能；本质就是一个闭包函数
- 原始方式：`comment = check(comment)` —— 手动把原函数传给装饰器再赋回来
- 语法糖：`@check` 写在函数定义上方，等价于 `comment = check(comment)`；`@classmethod/@staticmethod`（Day02 见过）也是装饰器

### 6. 企业开发用法【实操】
- 装饰器单独放一个 py 文件；使用处三种导入：`from 模块 import 装饰器` → `@装饰器`；`import 模块` → `@模块.装饰器`；`import 模块 as m` → `@m.装饰器`

### 7. 计算执行时间案例【实操】
- `begin = time.time()` → `fn()` → `end = time.time()` → 打印 `end - begin`

### 8. 嵌套装饰器【易错，顺序题考点】
- **由下往上装饰、由上往下运行**：`@outer1` 在上、`@outer2` 在下 → 等价 `func = outer2(func)` 然后 `func = outer1(func)`
- 运行效果：先走 outer1 的前半段 → outer2 的前半段 → 原函数 → outer2 后半段 → outer1 后半段

### 9. 带参数的函数用装饰器【实操】
- inner 的参数要对应被装饰函数的参数：`def inner(num1, num2)`，或通用 `def inner(*args, **kwargs)`，调用时 `fn(*args, **kwargs)`

### 10. 带返回值的函数用装饰器【易错】
- 被装饰函数有 return 时，inner 里必须**接收并返回**：`result = fn(...)` → `return result`；不写 return，调用方拿到的是 **None**

### 11. 通用模板（背下来）【掌握】
```python
def outer(fn):                      # fn = 被增强的函数
    def inner(*args, **kwargs):     # ① 有嵌套
        # 增强代码（写在调用前）
        result = fn(*args, **kwargs)  # ② 有引用，接收返回值
        # 增强代码（写在调用后）
        return result               # 把返回值传回去
    return inner                    # ③ 有返回（返回函数地址！）
```
五要素：嵌套 / 引用 / **返回 inner（不是 inner()）** / 不定长参数 / return result

### 12. 装饰器带参数【了解】
- 装饰器自身要传参（如 `@logging('+')`）时，在普通装饰器外**再套一层**函数接收参数 → 三层结构：
`logging(flag)` → 返回 `decorator(fn)` → 返回 `inner`；`@logging('+')` 等价 `func = logging('+')(func)`

### 13. 案例与课后练习【实操】
- 案例一：登录 + 验证码两个装饰器叠在评论功能上
- 案例二：一个装饰器同时支持加减（用装饰器参数 flag 区分）
- 课后①：用装饰器统计函数被调用次数
- 课后②：正整数计算器 —— 装饰器校验 num1/num2 必须是正整数

### 练习代码里发现的 bug（详见 复盘/模糊知识点.md）

- ❌ **`logDecorator.py` / `日志封装的函数.py`：`fn()` 被调用了两次**！inner 里先 `fn()` 计时，最后又 `return fn()`。实测 `案例.py` 中每个函数体打印两遍。**这是装饰器最危险的 bug**：被装饰函数执行两遍 = 副作用翻倍（扣款扣两次、消息发两次）。正确写法：`result = fn()` 接住 → 计时 → `return result`
- ❌ **`通用模板.py`：`return inner()` 应为 `return inner`**！模板文件本身就是错的。`return inner()` 会在**装饰时**立刻执行 inner（立刻执行被装饰函数），且函数名被替换成 inner 的返回值（None），之后调用会报 `TypeError: 'NoneType' object is not callable`。照这个模板写必炸 —— 这是装饰器最经典的错误，课件 3.6 节特别演示过 `return inner` 返回的是内存地址
- ⚠️ **`作业.py`：inner(*args, **kwargs) 但调用 `fn()` 没传参** —— my_count 恰好无参数所以能跑，但装饰任何带参函数都会 TypeError；且没接收返回值。属于"会跑但不通用"
- ⚠️ **`函数返回值.py` 是空文件** —— 课件第 10 节（带返回值的装饰器，temp_total 版本）没有练习
