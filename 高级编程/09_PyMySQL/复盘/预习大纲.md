## 1. Python 操作 MySQL —— 明日核心

### 1.1 为什么学（理解动机，别跳过）

- 引出问题：**如何把 10 万条数据插入 MySQL？** 用客户端手插不现实 → 用程序代码连接数据库做增删改查，即**数据库编程**。
- 前置准备：课前先把笔记 1.2.1 的建库建表 SQL 跑通（`jing_dong` 库 + `goods` 表 + `user` 表），否则课上没数据可查。
- 环境：`conda env list` 确认环境 → `conda activate 环境名` → `pip install pymysql`（清华源加速：`-i https://pypi.tuna.tsinghua.edu.cn/simple/`）。

### 1.2 六步口诀（必须能默写）

```
1.导入模块 → 2.创建连接 → 3.创建游标 → 4.执行SQL → 5.关闭游标 → 6.关闭连接
```

- `connect()` 五参数：`host / port / user / password / database`
- `cur.execute(sql)` 的**返回值 = 影响行数**（不是查询结果！）

### 1.3 查询：两个取数方法

| 方法 | 行为 | 记忆点 |
|------|------|--------|
| `fetchone()` | 一次只取 1 条 | 一条一条拿 |
| `fetchall()` | 一次取完**剩下的**所有数据 | 不是"全部"，是"剩下" |

### 1.4 增删改的隐形门槛：事务

- 事务特性：**ACID**（原子性 / 一致性 / 隔离性 / 持久性）
- 存储引擎差异：**InnoDB 支持事务，MyISAM 不支持**
- InnoDB 表上增删改**必须手动 `conn.commit()`**，否则"执行成功"也不会真正落库
- 出异常时 `conn.rollback()` 回滚（笔记"删"的示例里有 try/except + rollback 的完整写法）

### 1.5 登录案例 → SQL 注入 → 参数化（明日最高频考点）

**注入原理**（理解它才能防它）：

- 危险写法：`f"select * from user where user='{username}' and pwd='{password}'"`
- 密码输入 `' or 1=1 --` → SQL 变成 `... pwd='' or 1=1 --'`，恒为真，直接登录成功

**正确姿势**（三件事缺一不可）：

```python
sql = "select * from user where user=%s and pwd=%s"  # ① SQL 单独定义
parm = [username, password]                          # ② 参数放列表
row = cur.execute(sql, parm)                         # ③ 一起传给 execute
```

> 注意：占位符统一用 `%s`（值是数字也是 `%s`），不是 f-string 的 `{}`。

## 2. Redis 概述与安装 —— 概念 + 环境准备

### 2.1 三个问题串起概念

| 问题 | 答案要点 |
|------|---------|
| 是什么？ | 开源、**基于内存**的键值对存储数据库，可作**数据库 / 缓存 / 消息中间件** |
| 有什么特点？ | 内存运行→读写极快；持久化（**RDB 快照 + AOF 日志**）；5 大数据类型；事务原子性；发布/订阅、键过期 |
| 用在哪儿？ | 缓存系统（减数据库压力）、计数器、消息队列、排行榜、会话存储 |

### 2.2 安装与验证（Windows 用"小皮"最省事）

- 验证标准就一条：`redis-cli` 里 `ping` 返回 `PONG`，`set` / `get` 正常。
- macOS / Linux 安装部分浏览即可（工作机是 Windows）。

## 3. Python 操作 Redis —— 核心

### 3.1 连接：两个参数一个都不能少

```python
r = redis.Redis(host='localhost', port=6379, db=0,
                decode_responses=True,  # 不加 → 返回 bytes，全是 b'xxx'
                protocol=2)             # redis-py 新版默认 RESP3，不兼容要强制 RESP2
```

- 装包：`pip install redis`（笔记里"装 4.5.0"和代码里 `protocol=2` 互相矛盾——`protocol` 参数是 5.0+ 才有的，**装完自己验证一下，课上以实际能跑通的版本为准**）。

### 3.2 五大数据类型 API 速查表

| 类型 | 常用操作 | 对应场景 |
|------|---------|---------|
| String 字符串 | `set/get/mset/mget/setex`、`incr/incrby/decr/decrby` | 计数器 |
| Hash 哈希 | `hset/hget/hgetall/hkeys/hvals/hdel`、`hmget` | 存对象（user:1001） |
| List 列表 | `lpush/rpush/lrange/llen/lpop/rpop` | 消息队列 |
| Set 集合 | `sadd/smembers/sismember/scard/spop/srem`、`sinter/sunion/sdiff` | 去重、共同标签 |
| Sorted Set 有序集合 | `zadd/zrange/zrevrange/zscore/zincrby/zrevrank/zrangebyscore`（`withscores=True`） | 排行榜 |

### 3.3 键操作与过期时间

`exists`（存在？）/ `expire`（设过期秒数）/ `ttl`（剩多少秒）/ `setex`（设值+过期一步到位）/ `persist`（取消过期）/ `keys('session:*')`（模式匹配）/ `delete`

### 3.4 实战压轴：缓存系统

- 思路三步：`json.dumps` 序列化后 `setex` 存 → `get` 后 `json.loads` 反序列化取 → 判断"缓存命中 / 未命中"
- 验证点：`expensive_operation` 模拟 2 秒计算，第一次 2 秒、第二次从缓存 0 秒
- 这堂课的两个大实战正好首尾呼应：**PyMySQL 把数据存进磁盘库，Redis 把热数据放进内存**。

## 6. 易错预警（提前打预防针，课堂重点盯）

| # | 坑 | 后果 | 对策 |
|---|----|------|------|
| 1 | 忘写 `conn.commit()` | 增删改"成功"但数据没落库 | InnoDB 增删改必 commit |
| 2 | 以为 `execute` 返回查询结果 | 拿到的是影响行数 | 结果要用 fetchone/fetchall 取 |
| 3 | 以为 fetchall 取"全部" | 游标只会前进，先取过就拿不全 | fetchone 和 fetchall 二选一 |
| 4 | f-string 拼 SQL | 被 `' or 1=1 --` 注入 | %s 占位 + 参数列表 |
| 5 | 忘加 `decode_responses=True` | 全是 `b'xxx'` 字节 | 连接时必带 |
| 6 | redis-py 版本混用 | `protocol=2` 与旧版不兼容 / 旧 API（`hmset`、`zrevrange`）在新版报错 | 统一装一个版本，跑通为准 |
