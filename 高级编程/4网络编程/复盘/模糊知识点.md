## 一、网络基础概念
- [ ] **网络三要素** —— 协议（规范怎么传数据）/ IP（找设备）/ 端口（找设备上的程序），三者各管什么容易混
- [ ] **IP 的作用** —— 唯一标识一台设备（像手机号）；IPv4 现在用 / IPv6 未来用
- [ ] **域名 vs IP** —— 域名是 IP 的别名（www.baidu.com → 具体 IP）
- [ ] **端口分类三段** —— 知名 0-1023（HTTP 80 / HTTPS 443 / SSH 22 / FTP 21 / SMTP 25）；注册 1024-49151（MySQL 3306 / Redis 6379 / ollama 11434）；动态 49152-65535（系统随机分配、用完回收）。开发建议 8000 以后
- [ ] **http vs https** —— 80 不加密 / 443 加密

## 二、HTTP 协议
- [ ] **请求协议三部分** —— 请求行（请求方式 + 请求路径）、请求头（浏览器本地信息）、请求体（客户端真实要传输的数据）
- [ ] **请求方式** —— GET 查询 / POST 新增 / PUT 修改 / DELETE 删除
- [ ] **响应协议三部分** —— 响应行（状态码）、响应头、响应体（网页真正展示的内容）
- [ ] **状态码含义** —— 1xx-5xx；200 成功 / 304 本地有缓存 / 404 资源找不到 / 500 服务器代码报错
- [ ] **requests 扩展** —— `requests.get(url)` → `responses.content.decode()` 拿网页内容

## 三、TCP / UDP
- [ ] **TCP 三特点** —— 面向连接、可靠、基于字节流；步骤：建立连接 → 传输数据 → 关闭连接（像打电话）
- [ ] **TCP 可靠的四个机制** —— 发送应答、超时重传、错误校验、流量控制（避免发太快对方来不及收）；连接基于三次握手、四次挥手
- [ ] **TCP vs UDP** —— 需要可靠性用 TCP（日常通信）；只要速度不要质量用 UDP（视频通话）

## 四、编码转换
- [ ] **encode vs decode 方向** —— 发送：字符串 `encode('utf-8')` → 二进制 bytes；接收：`decode('utf-8')` → 字符串。方向反了会报错
- [ ] **为什么网络要编码** —— 网络中数据都以二进制传输

## 五、socket 编程（重点中的重点）
- [ ] **socket 是什么** —— 程序间网络通信的「约定/工具」（像电话机），只靠 IP + 端口还不够
- [ ] **创建套接字两个参数** —— `AF_INET` IPv4 / `AF_INET6` IPv6；`SOCK_STREAM` TCP / `SOCK_DGRAM` UDP
- [ ] **TCP 客户端五步** —— 创建 → connect → send → recv → close
- [ ] **TCP 服务端七步** —— 创建 → bind → listen → accept → recv → send → close（比客户端多 bind 和 listen）
- [ ] **connect 参数必须是元组** —— `connect(("ip", 端口))`；ip 是字符串、端口是整型
- [ ] **accept() 两个返回值** —— `conn_socket, ip_port = accept()`：新套接字（用来和这个客户端通信）+ 客户端 (IP, 端口)；后续收发用的是 conn_socket，不是原来的监听套接字
- [ ] **bind 空字符串** —— `bind(("", 8888))` 表示绑定本机所有 IP（等价 0.0.0.0）
- [ ] **listen(128)** —— 参数是全连接队列最大容量（等待 accept 的连接数）
- [ ] **recv 是阻塞 IO** —— 没数据时卡住等待；**收到空字符串 = 客户端已关闭**（多轮对话里用它来 break）
- [ ] **端口复用** —— `setsockopt(SOL_SOCKET, SO_REUSEADDR, True)`，防止服务重启时报端口占用
- [ ] **多轮对话双循环** —— 外层 while True 接收多个客户端；内层 while True 为某一个客户端多轮对话（内层退出后外层继续 accept 下一个）

## 六、飞秋 / UDP 扩展
- [ ] **UDP 发送用 sendto** —— `sendto(data, (ip, 端口))`，不是 send/connect
- [ ] **飞秋编码是 gbk** —— 不是 utf-8！`content.encode('gbk')`
- [ ] **群发要开广播** —— `setsockopt(SOL_SOCKET, SO_BROADCAST, 1)` + 广播地址（如 192.168.109.255）+ 2425 端口

## 七、代码复盘发现的问题（2026-11-14 新增，来源：我的代码 `代码/*.py`）
- [ ] **客户端关闭判断** —— 多轮对话服务器.py 写成了 `recvDate == " "`（空格），应改 `== ''`（空串）：客户端断开时 recv 返回 `b''`，decode 后是空串，不是空格
- [ ] **内层循环 try/except** —— 多轮对话服务器.py 没兜底，客户端异常断开服务器会崩（课件版有 try/except + close 释放资源）
- [ ] **listen(128) 含义** —— 全连接队列最大容量（等待 accept 的连接数），不是"同时服务多少个程序"
- [ ] **accept 返回值 2** —— 是 (客户端IP, 客户端端口) 的地址元组，不只是端口号
- [ ] **回环地址写法** —— `127.0.0.1`（服务器端.py 注释写成了 127.1.1.0）
- [ ] **SO_REUSEADDR 没练过** —— 课件 3.2.5 有，我的代码一次没用过，要补（连续重启服务端会报端口占用）
- [ ] **飞秋循环发送要 sleep** —— 飞秋点对点.py 的 `while True` 无限刷屏发送，`import time` 导入了没用
- [ ] **TCP 字节流无边界** —— 一次 send 可能需多次 recv 收完；client.py 单次 `recv(4096)` 长输出会截断并污染下一条命令
- [ ] **subprocess 要加 timeout** —— server.py `subprocess.run(command, shell=True)` 没有超时，`ping -t`/`notepad` 这类不自己结束的命令会让服务端永久卡死（2026-11-14 晚复查新增）
