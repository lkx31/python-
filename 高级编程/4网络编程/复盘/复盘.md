## 二、今日核心知识点总结

### 1. 计算机网络概述【知道】

- **网络三要素**：IP 地址找设备、端口找设备上的程序（如飞秋默认端口 2425）、协议规范双方怎么传数据
- **HTTP 协议**：请求 = 请求行（GET 查询 / POST 新增 / PUT 修改 / DELETE 删除 + 请求路径）+ 请求头（浏览器本地信息）+ 请求体（客户端真实要传输的数据）；响应 = 响应行（状态码）+ 响应头 + 响应体（网页真正展示的内容）
- **状态码**：200 成功 / 304 本地有缓存 / 404 资源找不到 / 500 服务器代码报错（按 1xx-5xx 分段）
- **IP 与域名**：IP 唯一标识设备（像手机号）；IPv4（4 段数字，如 192.168.46.72）目前使用、IPv6 未来使用；域名是 IP 的别名；http 默认 80 不加密、https 默认 443 加密
- **端口三段**：知名 0-1023（HTTP 80 / HTTPS 443 / SSH 22 / FTP 21 / SMTP 25）、注册 1024-49151（MySQL 3306 / Redis 6379 / Ollama 11434）、动态 49152-65535（系统随机分配、用完回收）；开发建议 8000 以后
- **TCP vs UDP**：TCP 面向连接、可靠（发送应答 / 超时重传 / 错误校验 / 流量控制，连接基于三次握手、断开四次挥手）、基于字节流，像打电话；UDP 不可靠但快，适合视频通话

### 2. Python3 编码转换【实操】

- 网络中数据以二进制传输：发送 `字符串.encode('utf-8')` → bytes；接收 `bytes.decode('utf-8')` → 字符串
- 今天所有代码都在用这一对；方向记反会直接报错

### 3. socket 编程【实操 · 重点中的重点】

- **socket**：程序之间网络通信的约定/工具（像电话机），只靠 IP + 端口还不够
- **创建套接字**：`socket.socket(socket.AF_INET, socket.SOCK_STREAM)` —— AF_INET = IPv4、SOCK_STREAM = TCP（UDP 用 SOCK_DGRAM）
- **客户端五步**：创建 → `connect(("ip", 端口))`（**参数必须是元组**，ip 字符串、端口整型）→ `send(data)` → `recv(1024)` → `close()`
- **服务端七步**：创建 → `bind(("", 端口))` → `listen(128)` → `accept()` → `recv` → `send` → `close`（比客户端多 bind、listen 两步）
- **accept()**：阻塞等待连接；返回 `(conn_socket, (ip, port))` —— 后续收发全部用新套接字 conn_socket，不是原来的监听套接字
- **bind 的 IP 写法**：`"127.0.0.1"` 只有本机能访问；`"192.168.x.x"` 同网段可访问；`"0.0.0.0"` 或 `""` 所有人都能访问
- **listen(128)**：参数是全连接队列最大容量（等待 accept 的连接数），**不是"同时服务多少个程序"**
- **recv**：阻塞 IO（没数据时卡住等）；**收到空字节串 `b''` = 对方已关闭连接**（多轮对话靠它退出内层循环）
- **端口复用**：`setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, True)` —— 服务重启后立刻能再绑定端口，不报端口占用
- **多轮对话双循环**：外层 `while True` 循环 accept 接多个客户端（挨个对话）；内层 `while True` 为当前客户端多轮收发；内层 break 后回到外层继续 accept 下一个

### 4. 飞秋 UDP 扩展【扩展】

- UDP 发送用 `sendto(数据, (ip, 端口))`，不需要 connect
- 飞秋协议：端口 2425，**编码是 gbk 不是 utf-8**；消息格式 `'1:发送者ID:昵称:群组:接收者ID:消息正文'`
- 群发：先 `setsockopt(SOL_SOCKET, SO_BROADCAST, 1)` 开广播，地址用广播地址（如 192.168.109.255）

## 三、模糊知识点 / 代码里发现的问题（对比课件）

> `我的笔记.md` 为空，所以本环节以 `代码/*.py` 为证据逐文件核对课件。❌ = 代码 bug，⚠️ = 理解或写法不准确。

### 多轮对话服务器.py（今天最需要修的一个文件）

- ❌ **客户端关闭判断写错了：`recvDate == " "`（一个空格）**。课件写法是 `recvData == ''`（**空字符串**）。客户端断开后 recv 返回 `b''`，decode 后是 `''`，永远不等于 `' '` → 检测不到客户端关闭 → 继续 recv 阻塞，或向已关闭的连接 send 直接抛 ConnectionResetError 崩溃。**必须改成 `if recvDate == ''`（或 `if not recvDate`）。**
- ❌ **内层循环没有 try/except**。课件版本用 try/except 兜住客户端异常断开并 `connect_socket.close()` 释放资源；现在的版本客户端强关窗口时服务器直接崩。
- ⚠️ 外层 `while True` 之后的 `tcp_server_socker.close()` 是死代码（永远执行不到）——服务器靠 Ctrl+C 退出可以接受，但要知道这行没生效。

### 服务器端.py（基础七步版）

- ⚠️ 注释把回环地址写成了 **`127.1.1.0`**，正确的是 `127.0.0.1`（本机专用）。IP 地址一个数字都不能错。
- ⚠️ 注释"开启监听:同时监听多少个程序" —— **listen(128) 不是"服务多少个程序"**，是全连接队列最大容量（等待 accept 的连接数）。
- ⚠️ accept 注释"参数2端口号" —— 第二个返回值是 **(客户端IP, 客户端端口) 的地址元组**，不只是端口号。

### 飞秋点对点.py

- ⚠️ 自己加的 `while True` 会让同一条消息**无限刷屏发送**（对方飞秋窗口会被刷爆）；`import time` 导入了却没用来 sleep —— 本意应该是 `time.sleep(间隔)` 控制频率。
- ⚠️ 只练了点对点；课件 3.2.6 还有**群发版**（`SO_BROADCAST` + `192.168.xxx.255` 广播地址）没练。

### client.py / server.py（远程命令执行，自学扩展）

- ⚠️ 客户端 `recv(4096)` 只收一次：命令输出超过 4096 字节时只显示前半截，剩下的字节残留在缓冲区、**污染下一条命令的结果**。TCP 是字节流、没有"一条消息"的边界，长数据要循环 recv 直到收完。
- ⚠️ server.py 没加 `SO_REUSEADDR`：连续重启服务端容易报"端口被占用"（正好可以补上课件 3.2.5 的端口复用练习）。
- ⚠️ **（复查新增）server.py `subprocess.run(command, shell=True)` 没有 timeout**：执行 `ping -t`、`notepad`、交互式命令这类"不自己结束"的命令时，服务端会永远卡在这行，控制端也永远等不到返回，只能 Ctrl+C 强杀。建议 `subprocess.run(command, shell=True, capture_output=True, timeout=10)`，并 try/except `TimeoutExpired` 给控制端回一句"命令超时"。

- ⚠️ 课件所有示例都包了 `if __name__ == '__main__':`，我的代码没写——功能不受影响，但养成习惯更好。
