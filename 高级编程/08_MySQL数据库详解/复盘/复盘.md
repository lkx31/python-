## 二、今日核心知识点总结

### 1. 库操作【必会，✓ 已练】
```sql
create database [if not exists] 库名 [character set utf8];   -- if not exists 防重复报错
use 库名;                                                    -- 切换库（操作表的前提）
show databases;                                              -- 查看所有库
```
今天亲手建了 `day07` 库（两条 create，第二条带 charset——因 if not exists 已存在被忽略，练习了语法）。

### 2. 建表 + 约束入门【重点，◐ 练了一半】
```sql
create table 表名(字段名 字段类型 [字段约束], ...);
```
- 练到的约束：`primary key`（主键=身份，**唯一+非空**）、`not null`（不能为空）
- 一个表只能有一个主键；主键是整型时通常加 `auto_increment` 自增
- 没练的约束：`unique`、`default`、`auto_increment`（自己写表时）、`foreign key`

### 3. DML 增删改【重点，◐】
```sql
insert into 表名 (字段名...) values (值...), (值...);  -- 值与字段一一对应；多条逗号分隔
update 表名 set 字段=值 [where 条件];                  -- 不加 where = 改全表（慎用）
delete from 表名 [where 条件];                        -- 不加 where = 删全表（慎用）
truncate [table] 表名;                                -- 清空 + 自增重置（今天没练）
```
- 关键体验：`update student set name="lkt" where name="rose"` 一次更新了**所有** name='rose' 的行——因为表没有主键，where 命中多少就改多少。

### 4. 单表查询 DQL【核心，◐ 缺分组和分页】
- **基础**：`select [distinct] 字段|* from 表名`；`as` 起别名（可省略 as）；**给表起别名后必须用别名调字段**（练了 `p.name`）
- **条件**：比较 `> < >= <= !=`；逻辑 `and`；范围 `between x and y`（**含边界**、连续范围，不能写 `1000 <= price <= 3000`）；模糊 `like` + `%`（任意多个字符）；判空 `is null`
- **排序**：`order by 字段 desc`（asc 是默认值）
- **聚合函数**：`sum() count() avg() max() min()`——自动**忽略 null**，统计个数用 `count(*)`
- **⚠️ 今天没练的**：`group by`/`having`（4.6）、`limit` 分页（4.7）、`in`、`_`、`not`、`is not null`、多字段排序

### 5. 多表连接【核心，✓ 内/左/右练得很全】
| 连接 | 关键字 | 结果 | 今天 |
|---|---|---|---|
| 内连接 | `inner join ... on` | 两表**交集**（匹配不上的都不要） | ✓ 4 种写法都跑了 |
| 左外连接 | `left join ... on` | **左表为主**，右表无匹配补 null | ✓ 两表各当左表都试了 |
| 右外连接 | `right join ... on` | **右表为主**，左表无匹配补 null | ✓ 同上 |
| 全外连接 | MySQL **没有** full join | 左连接 `union`（去重）/`union all`（不去重）拼右连接 | ◐ 只练了 union all |

左/右连接的 4 个方向组合（products/category 各当一次主表）都跑了——这个练法很好，"以谁为主"的理解是到位的。

## 三、模糊知识点（今天笔记为空 → 以代码为证据 + 本机 MySQL 实测）

> 今天 `我的笔记.md` 是空文件，所以「笔记里没写清楚的地方」换成「代码里暴露的模糊点」，全部用本机 MySQL 8.0.12 实际验证过。

- ⚠️ **null 三兄弟没分清，还写错了一个**。老师的核心结论：sql 的 `null` ≠ 空字符串 `''` ≠ 字符串 `'null'`，判空只能 `is null`。你在代码 L113 写的是 `where name=' '`（**一个空格**），课件写的是 `''`（空串）。已验证 MySQL 比较字符串时**忽略尾部空格**（`'' = ' '` 结果是 1/TRUE），所以你的查询"歪打正着"能查到——但这是巧合：换成 `like ' '` 就查不到了。概念上 `''`、`' '`、`'null'`、`null` 是四样东西，一个都不能混。
- ⚠️ **字符串用双引号**。代码里大量 `"jack"`、`"rose"`、`"自营"`（L16-17、22、36、94）。MySQL 默认把双引号当字符串，所以都能跑（已验证 stu3 的 GTA1 插进去了）——但 SQL 标准是**单引号**，如果哪天开了 `ANSI_QUOTES` 模式，双引号会被当成列名直接报错。习惯从现在改成单引号。
- ⚠️ **`value` 和 `values`**。老师课件全用 `values`（标准写法），你写的 `insert ... value (...)`。MySQL 兼容单数所以能用，但建议统一 `values`。
- ⚠️ **主键的用法偏了**。stu3 用 `game varchar(10) primary key`（游戏名当主键）。能跑，但主键=身份，老师模式是 `id int primary key auto_increment`。业务字段（游戏名、用户名）会变、会重复、会改名，当主键后期全是坑；另 `phone varchar(10)` 存不下 11 位手机号。
- ⚠️ **「没有约束 → 数据无法区分」你今天亲手制造了活案例**。已验证 day07.student 表现在有 **6 行一模一样的 `lkt 25 111 2001-01-11`**——因为表没建主键/唯一约束，重复执行插入没有任何拦阻，多跑几遍就堆出重复数据。这正好是老师讲约束的第一句话。给 student 加个 `id int primary key auto_increment` 重建一遍，感受一下区别。
- ⚠️ **`select is_self, avg(score) from products where is_self='非自营';` 为什么没报错**（老师示例3，你也抄了）。规则说 select 后的裸字段要么在 group by 里、要么在聚合函数里，`is_self` 两不沾，但实测能跑（返回 非自营/9.28）。原因：没有 group by 时整表是一个大分组，且 MySQL 8.0 能识别 where 把 `is_self` 钉死成了单个值。不用深究，但背规则时知道有这种"整表=一个分组"的情况即可。
- ⚠️ **聚合函数忽略 null 没验证**。已验证 my_db.products 共 15 行，`count(*)`=15、`count(score)`=**11**（阿玛尼红管405 和后面补插的 3 条 score 都是 null）。这个对比就是"统计个数用 count(*)"的原因，亲手跑一遍比背十遍管用。

## 五、课件易错点核对清单（复习自测）

- [ ] **null / '' / 'null' 三兄弟**：判空只能用 `is null`；`score = null`、`score = ''`、`score = 'null'` 全是错的
- [ ] **delete vs truncate**：delete 清空后自增序号**保留**；truncate 清空后自增**重置**（下次从 1 开始）
- [ ] **where vs having**（必考四点）：书写 where 前 having 后；执行 where 分组前 having 分组后；where 后不能跟聚合条件；where 不能用别名、having 可以
- [ ] **count(字段) vs count(\*)**：聚合函数忽略 null；统计个数用 `count(*)`（实测 15 vs 11）
- [ ] **连续范围**只能 `between 1000 and 3000`，不能写 `1000 <= price <= 3000`（语法错误）
- [ ] **like 通配符**：`%` 任意多个字符、`_` 恰好一个字符
- [ ] **起别名后必须用别名**：`select name from products as p` 是错的，必须 `p.name`
- [ ] **DML 忘写 where = 操作全表**（工具弹黄警告，慎点 execute）
- [ ] **MySQL 没有 full outer join**：用 `union`（去重）/`union all`（不去重）拼左右连接
- [ ] **自连接必须起别名**（一张表当两张表用，不起别名无法区分）
- [ ] **书写顺序 ≠ 执行顺序**：执行从 `FROM` 开始（FROM→WHERE→GROUP BY→聚合→HAVING→SELECT→DISTINCT→ORDER BY→LIMIT），这解释了为什么 where 里不能用别名/聚合结果
- [ ] **分组查询**：select 出现 group by 之外的裸字段会报错（only_full_group_by，你们库的 sql_mode 里确实开着，已确认）
- [ ] **insert 三注意**：值与字段一一对应；全字段可省略字段名；多条用逗号分隔
- [ ] **主键 = 唯一 + 非空**，但唯一+非空 ≠ 主键；一个表只能一个主键；auto_increment 用 0 或 null 占位自动递增
