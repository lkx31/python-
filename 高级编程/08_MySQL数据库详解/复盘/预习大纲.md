## 二、核心知识框架

### 1. 数据库概述（了解）

- **数据库**：有组织、可高效访问和管理的电子化数据集合；实际由「数据库本身 + DBMS」两部分组成。
- **DBMS**（数据库管理系统）：用户/程序与数据库之间的接口，代表：MySQL、Oracle、SQL Server。
- **关系型**：二维表（行=记录，列=字段），术语：主键（唯一标识）、外键（表间关系）、SQL 查询；ACID 保证强一致性。代表：MySQL、Oracle、PostgreSQL。
- **非关系型**：无固定表结构，类型有键值型(Redis)、文档型(MongoDB)、列族型(HBase)、图数据库(Neo4j)。
- **选型**：关键业务/复杂关联查询 → SQL；海量非结构化/高写入/水平扩展 → NoSQL。

### 2. SQL 语言基础（必会）

**SQL 五大分类**：

| 分类 | 作用 | 关键字 |
|---|---|---|
| DDL 数据定义 | 定义库、表、字段等**结构** | create / drop / alter |
| DML 数据操作 | 表中记录的**增删改** | insert / delete / update |
| DQL 数据查询 | 表中记录的**查询**（约定俗成，非官方） | select / from / where |
| DCL 数据控制 | 权限、安全级别、创建用户 | grant / revoke |
| TCL 事务语言 | 事务控制 | commit / rollback |

**通用语法规则**：
- 以 `;` 结尾，可换行/缩进增强可读性
- 不区分大小写，关键字建议大写（快捷键 ctrl+shift+u）
- 注释：`/**/` 多行；`-- `（后必须有空格）、`#` 单行（快捷键 ctrl+/、ctrl+shift+/）

### 3. MySQL 连接（每天都要用）

- 命令行登录：`mysql -u用户名 -p密码` / `mysql -h主机 -p`（localhost = 本机）
- 登出：`exit` / `quit` / `\q`
- 图形工具（DataGrip 等）：连接服务 → 关联驱动 → 可设置字体、主题、方言

### 4. 库的操作（必会）

```sql
create database [if not exists] 库名;   -- 创建（可加 CHARACTER SET utf8）
use 库名;                                -- 切换
show databases;                          -- 查看所有库
drop database [if exists] 库名;          -- 删除（拓展）
```

### 5. 数据类型与约束（★★ 重点）

**常用类型**：

| 类型 | 说明 | 记忆点 |
|---|---|---|
| varchar(n) | 可变长字符 | 存几个占几个 |
| char(n) | 固定长字符 | 不够 n 用空格补齐 |
| int / bigint | 整数 | int 默认长度 11，不够用 bigint |
| float / double / decimal | 小数 | decimal(11,2)：总长 11、小数 2 位（**存钱用 decimal**） |
| date / datetime / year | 日期时间 | 生日用 date |

**六大约束**：

| 约束 | 关键字 | 特点 |
|---|---|---|
| 主键 | primary key | 非空 + 唯一；一表只能一个 |
| 自增 | auto_increment | 修饰主键；插 0 / null 占位自动递增 |
| 非空 | not null | 值不能为空 |
| 唯一 | unique | 值不能重复 |
| 默认 | default | 不传值时用默认值 |
| 外键 | foreign key | 保证完整性：限制从表插入，限制主表删除 |

> ⚠️ 易混：唯一+非空 ≠ 主键（主键还代表"身份"，且一个表只能有一个）。

### 6. 表的操作（必会）

```sql
create table 表名(
    字段名 字段类型 [字段约束],
    字段名 字段类型 [字段约束] ...
);
show tables;        -- 查看所有表
desc 表名;          -- 查看字段信息
```

> 操作前提链：**连库 → 有库（use）→ 有表 → 有字段**，才能操作数据。

### 7. 记录增删改 DML（★★ 重点）

```sql
-- 增：值与字段一一对应；全字段可省略字段名；多条用逗号分隔
insert into 表名 (字段名...) values (值...), (值...);

-- 改：不加 where 改全表（慎用！）
update 表名 set 字段=值[, 字段=值] [where 条件];

-- 删：不加 where 删全表（慎用！）
delete from 表名 [where 条件];

-- 清空全表两种方式的区别（高频面试点）：
delete from 表名;      -- 自增序号保留，下次继续递增
truncate [table] 表名; -- 自增序号重置，下次从 1 开始
```

### 8. 单表查询 DQL（★★★ 核心）

查询格式（完整版，**书写顺序**）：

```
select [distinct] 字段|*|聚合函数 [as 别名]
from 表
[where 条件]        -- 分组前过滤，非聚合条件
[group by 字段]     -- 分组
[having 条件]       -- 分组后过滤，可用聚合条件
[order by 字段 asc|desc, 字段2 ...]
[limit x, y];       -- 分页：x 起始索引(默认0)，y 条数；x=(页数-1)*y
```

**执行顺序（理解查询的关键）**：
`FROM → WHERE → GROUP BY → 聚合 → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT`

| 模块 | 关键点 |
|---|---|
| 基础查询 | `distinct` 去重；`as` 别名（起别名后**必须用别名**调字段） |
| 条件查询 | 比较 `> < >= <= != <>`；逻辑 `and or not`；范围 `between x and y`（含边界）、`in(x,y)`；模糊 `like`（`%` 任意多个、`_` 一个）；空值 `is null` / `is not null` |
| 排序 | `order by` 多字段：先排前面的，相同再排后面的 |
| 聚合函数 | `count / sum / avg / max / min`；**自动忽略 null**；统计个数用 `count(*)` |
| 分组 | `group by`；select 后的字段要么在 group by 里，要么在聚合函数里，否则报错 |
| 分页 | `limit` 做 topN，但无法处理并列，后期用开窗函数解决 |

**where vs having（必考）**：
- 书写：where 在 group by **前**，having 在 **后**
- 执行：where 分组**前**过滤，having 分组**后**过滤
- 条件：where 后**不能**跟聚合条件；having 后可以（非聚合条件也能跟但不建议）
- 别名：where 后不能用，having 后可以用
- 原则：能用 where 就用 where，只有聚合条件才用 having

### 9. 多表查询（★★★ 核心）

**本质**：通过主外键关系把多张表 join 成一张大表再查。

- **多表关系**：一对一；一对多（分类↔商品）；多对多（借中间表拆成一对多）
- **外键**：从表（多方）字段引用主表（一方）主键；外键类型必须与主表主键类型一致

**join 家族**：

| 连接 | 关键字 | 结果 |
|---|---|---|
| 交叉连接（慎用！） | cross join（或 `from 左表,右表`） | 笛卡尔积 = 错误 |
| 内连接（常用） | `inner join ... on`（或 `from 左表,右表 where 条件`） | 两表**交集** |
| 左外连接 | `left outer join ... on` | 以**左表**为主，右表无匹配补 null |
| 右外连接 | `right outer join ... on` | 以**右表**为主 |
| 全外连接 | MySQL **没有** full join | 左连接 `union`（去重）/ `union all`（不去重）右连接 |

- **自连接**：同一张表当两张表关联（如省市县 areas 表），**必须起别名**
- **子查询**：select 中嵌套 select，被嵌入的为子查询，辅助主查询

### 10. 拓展（了解）

```sql
rename table 旧表名 to 新表名;          -- 改表名
show create table 表名;                 -- 查看建表语句
alter table 表名 add [column] 字段名 类型 [约束];       -- 加字段
alter table 表名 drop [column] 字段名;                  -- 删字段
alter table 表名 change 旧名 新名 类型 [约束];           -- 改名+改类型
alter table 表名 modify 字段名 类型 [约束];              -- 只改类型
```

## 三、易错点预警清单（预习时先打预防针）

1. **delete vs truncate**：清空全表后自增序号是否重置（前者保留、后者重置）
2. **count(字段) vs count(\*)**：聚合函数忽略 null，统计个数用 `count(*)`
3. **where vs having**：位置、执行时机、能否跟聚合条件、能否用别名
4. **null 三兄弟**：sql 的 `null` ≠ 空字符串 `''` ≠ 字符串 `'null'`；判空只能用 `is null`，`score = null` 是错的
5. **连续范围**：只能 `between 1000 and 3000`，不能写 `1000 <= price <= 3000`（语法错误）
6. **like 通配符**：`%` 任意多个字符、`_` 恰好一个字符
7. **起别名后必须用别名**：`select name from products as p` 是错的，必须 `p.name`
8. **DML 忘写 where** = 操作全表（工具会弹黄警告，慎点 execute）
9. **MySQL 没有 full outer join**，用 `union`（去重）/ `union all`（不去重）拼接左右连接
10. **自连接必须起别名**，否则无法区分两张"同名表"
11. **书写顺序 ≠ 执行顺序**：执行顺序从 `FROM` 开始，这解释了为什么 where 不能用别名/聚合结果
12. **分组查询**：select 出现 group by 之外的裸字段会报错（only_full_group_by）
