## 二、4.1 Python 中的生成器

### 核心概念（先理解再学语法）
- 生成器：**按规则循环生成数据**，条件不成立时生成结束
- 数据**不是一次性全部生成**，而是用一个生成一个 → **节约大量内存**

### 2.1 创建生成器方式一：生成器推导式
- 与列表推导式类似，区别在于用**小括号**
- 取值方式：`next(生成器)` / `for` 循环遍历 / 转成其他数据类型

```python
# 预习试写：创建生成器并取值
my_generator = (i * 2 for i in range(5))
print(my_generator)          # 打印的是生成器对象，不是数据
for value in my_generator:
    print(value)
```

### 2.2 创建生成器方式二：yield 关键字
- 特征：**def 函数中含有 yield 关键字**，该函数就是生成器函数

```python
# 预习试写：yield 生成器
def generator(n):
    for i in range(n):
        print('开始生成...')
        yield i              # 执行到 yield 暂停并返回结果
        print('完成一次...')  # 下次启动从这里继续

g = generator(5)
print(next(g))   # 取 5 次正常
print(next(g))   # 第 6 次报错：StopIteration
```

### 2.3 注意点（明天听课重点）
1. 执行到 **yield 会暂停**，把结果返回；下次启动生成器在**暂停的位置继续执行**
2. 数据生成完毕后再取 → 抛出 **StopIteration**（停止迭代异常）
3. while 循环内部**没有自动处理异常**，需手动处理
4. **for 循环内部自动处理**了停止迭代异常 → 推荐用 for

### 2.4 yield 与 return 的区别
| 对比项 | return | yield |
| :--- | :--- | :--- |
| 返回方式 | 直接返回**所有结果** | 返回可迭代的**生成器对象** |
| 函数状态 | 程序**终止**不再运行 | 挂起后可**恢复**继续执行 |
| 局部变量 | **销毁** | **保留** |

## 三、4.2 Python 中的协程

### 核心概念
- Python 的协程实现**从生成器发展而来**
- 协程：由 `async def` 定义的**异步函数**，由**事件循环**调度，通过 `await` **主动挂起**，实现**协作式并发**

| 特性 | 生成器 Generator | 协程 Coroutine |
| :--- | :--- | :--- |
| 主要目的 | 生成值序列 | 执行异步任务 |
| 控制流 | 单向：调用者 → 生成器 | **双向**：调用者 ↔ 协程 |
| 数据流向 | 数据向外流动 | 数据**双向**流动 |
| 调度 | 由调用者驱动 | 由**事件循环**调度 |
| 关键字 | `yield` | `async`、`await` |

### 协程三要素（必背）
1. 函数前加 **async**
2. 等待处加 **await**
3. 启动用 **asyncio.run**

### 使用三步骤（必背）
1. 定义 **async** 函数
2. 用 **create_task** 创建任务
3. 用 **await** 等待结果

```python
# 预习试写：协程完整案例
import asyncio

async def hello(name):                # 1. async 定义协程函数
    print(f"开始: {name}")
    await asyncio.sleep(1)            # 2. await 让出控制权
    print(f"结束: {name}")

async def main():
    await hello("Alice")              # 3. 单个协程调用
    # 4. 并发执行
    task1 = asyncio.create_task(hello("Bob"))
    task2 = asyncio.create_task(hello("Charlie"))
    await task1
    await task2

asyncio.run(main())                   # 5. 启动事件循环
```

> **一句话总结：协程让 I/O 等待时不闲着，去干其他事！**

## 四、4.3 协程 vs 线程 vs 进程

### 全方位对比表（明天要能自己复述）
| 对比项 | 协程 | 线程 | 进程 |
| :--- | :--- | :--- | :--- |
| 创建数量 | 轻松**上万** | 最多几百 | 最多几十 |
| 适用场景 | **I/O 密集**（网络、文件） | I/O 密集 | **计算密集** |
| 内存占用 | 很小（几 KB） | 较大（几 MB） | 很大（几十 MB） |
| 数据共享 | 直接共享 | 小心共享（**加锁**） | **不能**直接共享 |
| 一句话总结 | 单线程内切换做事 | 看起来同时做事 | 真正同时做事 |

### 应用场景选择指南（if/else 记忆法）
```
if   主要是网络请求 or 文件读写:   → 用协程   # I/O 密集型最佳选择
elif 主要是数学计算:               → 用多进程 # 绕过 GIL
else 简单的后台任务:               → 用多线程 # 简单易用
```

### 最简记忆法（魔术师比喻）
- **协程**：单线程魔术师，手里抛接多个球（I/O 等待时换件事做）
- **线程**：多个魔术师，但只有一个能表演（GIL 限制）
- **进程**：多个魔术师，各自独立表演（完全独立）

> 记住：Python 中**协程适合网络编程**（衔接已学的网络编程模块），网络等待时可以做其他事，效率最高。

## 七、易错点预警（来自老师笔记的坑）

1. 生成器取完值再取 → **StopIteration**（不要用 while 裸取，用 for）
2. `asyncio.sleep()` 才是异步等待，不能用 `time.sleep()` 阻塞事件循环
3. 协程函数（async def）**不能直接调用**，直接调用得到的是协程对象，需要用 `asyncio.run` 或 `await`
