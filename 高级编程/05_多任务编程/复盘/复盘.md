## 二、今日核心知识点总结

### 1. 多任务基础【知道】
- **为什么**：单任务程序一个函数执行完另一个才能执行；多任务能**充分利用 CPU 资源、提高执行效率**
- **并发**：一段时间内**交替**执行多个任务（单核 CPU 快速切换，看起来像同时）
- **并行**：一段时间内**真正同时**执行多个任务（多核 CPU 每个内核安排一个任务）
- 易混锚点：**单核只能并发，多核才能并行**

### 2. 多进程 multiprocessing【掌握】
- **概念**：进程是**资源分配的最小单位**，通俗理解「一个正在运行的程序就是一个进程」（运行中的 QQ、微信）
- **三步走**：
  ```python
  import multiprocessing                      # ① 导包
  p = multiprocessing.Process(target=study)   # ② 创建进程对象，target 传函数名不加括号！
  p.start()                                   # ③ 启动进程
  ```
- **传参**：`args=(3,)` 元组（**单个参数逗号不能省**，`(3)` 是 int 不是元组）；`kwargs={'count': 3}` 字典（**键必须与函数形参名一致**）
- **main 保护**：进程创建/启动代码要写在 `if __name__ == '__main__':` 里（Windows 必需，否则子进程会递归创建报错）
- **进程编号**：`os.getpid()` 当前进程、`os.getppid()` 父进程（p=parent）；`multiprocessing.current_process().pid` 也能拿，`.name` 拿进程名（主进程 MainProcess、子进程 Process-1）
- **不共享全局变量**：创建子进程 = **把主进程资源拷贝一份**，各进程操作各自的副本（双胞胎比喻）→ 互相独立
- **结束顺序（重要）**：
  - 默认方案：主进程代码不阻塞（会先打印完自己的代码），但**主进程退出前默认等待所有非守护子进程执行结束后一并销毁**
  - 方案一：`work_process.daemon = True`（**必须在 start() 之前设置**）→ 主进程退出，守护子进程直接销毁
  - 方案二：`work_process.terminate()` 让子进程直接销毁
  - 扩展：`进程.kill()`（和 terminate 一样）、`进程.join([timeout])`（阻塞等待进程结束，**要在 start() 之后调用**）、`进程.is_alive()`（判断是否还在运行）

### 3. 多线程 threading【掌握】
- **概念**：线程是**程序执行的最小单位**；进程只负责分配资源，**利用资源执行程序的是线程**；一个进程至少有一个线程；线程共享所属进程的全部资源（省资源，像同一个 QQ 开两个聊天窗口）
- **三步走**：`import threading` → `threading.Thread(target=函数名)` → `.start()`，参数表和进程一样（target/name/group/args/kwargs）
- **线程 id（了解）**：`threading.current_thread().ident`、`.native_id` 拿线程 id；`os.getpid()` 拿进程 id（同一进程的所有线程进程 id 相同）
- **守护线程**：`Thread(target=work, daemon=True)`（构造参数）或 `setDaemon(True)`（弃用，有警告）
- **执行顺序**：**无序**，由 CPU 调度决定哪个线程先执行
- **共享全局变量**：多个线程在同一个进程里，**共用同一份全局变量**（和进程相反！）
- **GIL 全局解释器锁**：CPython 同一时刻只允许一个线程执行 Python 字节码 → **多线程不能利用多核**；I/O 等待时锁会释放，所以线程适合 I/O 密集型
- **互斥锁 threading.Lock**：同一时刻只有一个线程能拿到锁，防止竞态条件
  - `lock.acquire()` 获取锁（被占用则**阻塞等待**）/ `lock.release()` 释放 / `lock.locked()` 检查是否被占用
  - 案例：全局 num 两个线程各累加 100 万次 —— 不加锁结果 < 200 万（`num += 1` 不是原子操作：读→加→写三步中途可能被切换），加锁后 = 200 万
- **死锁**：两个线程都在等对方释放资源，互相卡死
- **RLock 可重入锁**：同一线程可以重复 acquire 同一把锁，解决嵌套加锁；但比 Lock 慢
- **多线程三注意**：① 尽量不用全局变量 ② 能不用锁就不用 ③ 加锁不要放到循环里（把整个循环包在锁里）

### 4. 进程 vs 线程对比【背】
| 对比项 | 进程 | 线程 |
| :--- | :--- | :--- |
| 关系 | 线程依附进程，没有进程就没有线程 | 一个进程默认一条线程，可创建多条 |
| 全局变量 | **不共享** | **共享** |
| 资源开销 | 大（每次创建分配资源） | 小（共享进程资源） |
| 调度单位 | 资源分配的基本单位 | CPU 调度的基本单位 |
| 优缺点 | 优点可用多核（绕 GIL），缺点开销大 | 优点开销小，缺点不能用多核（GIL） |

## 三、我的笔记里的模糊知识点（对比课件逐条核对）

> ⚠️ = 表述不清，❌ = 写错了。今天笔记不算空（比网络编程那天好），但有 8 处以上写错或写不清。

- ❌ **"multipart process target" —— 模块名写错了**。课件原文拆词助记「multipart 多部分 + process 进程 + ing 正在进行时」是帮你记单词的，真正的模块名是 **`multiprocessing`**。另外"其中if要放到启动"表述不清，应为：**进程的创建和启动代码要放在 `if __name__ == '__main__':` 保护里**（Windows 必需，否则子进程递归创建报 RuntimeError）。
- ❌ **"__mp__main子线程的名称不等于主线程的名称main" —— 无法解读，需要重写**。正确关系：主线程名称是 `MainThread`，子线程默认 `Thread-1`、`Thread-2`…（用 `threading.current_thread().name` 查看）；进程同理（MainProcess / Process-1）。`__main__` 只是主程序脚本的模块名，和线程名没有关系。
- ❌ **"进程：资源分配和调度分配的最小单位" —— 把线程的活安到进程头上了**。课件 3.3.2 原话：**进程是操作系统资源分配的基本单位，线程是 CPU 调度的基本单位**。你后面写"多线程：是程序执行的最小单位"是对的，但进程这行要把"调度"去掉。
- ⚠️ **并发/并行只记了比喻，漏了锚点**。"一个人交替 / 多个人同时"的比喻可以，但要点是**单核 CPU 只能并发，多核 CPU 才能并行** —— 面试常问。
- ❌ **"os.kill（pid,-9）杀死进程==windows的结束进程" —— 混了两套东西**。① `-9` 是 Linux 的 SIGKILL 信号，Windows 没有这个信号；② 课件里杀死子进程用的是 Process 对象的方法 `进程.kill()` / `进程.terminate()`，**不是 os.kill**。
- ❌ **"主进程默认情况下不会等待子进程执行完毕后在继续执行" —— 和课件结论相反**。正确分两半：主进程的**代码**不会阻塞等待（"主进程执行完毕"会先打印出来），但**主进程退出前默认等待所有非守护子进程执行结束后一并销毁**（所以现象是：主进程打印完了、子进程还在输出、程序没有退出）。正因为默认会等，才需要 daemon=True / terminate() 两个方案。
- ⚠️ **"multiprocessing.current_process()pid" —— 少了个点号**。是 `current_process().pid`（先调用返回进程对象，再取属性）。顺带 `.name` 获取进程名称没记。
- ⚠️ **"多参数传递arg元组，kwargs字典" —— 漏了课件明确强调的两个坑**：① args 单个参数必须写 `(1,)`，逗号不能省；② kwargs 的键必须和函数形参名完全一致。
- ⚠️ **"进程.daemon=true" —— 漏了设置时机**：必须在 **start() 之前**设置（Python 里布尔值大写 `True`）。下一行"设置守护进程的属性 函数方法"没有实际内容。
- ⚠️ **"GIL：全局解释器锁" —— 只记了名字**。要补机制和后果：同一时刻只允许一个线程执行 Python 字节码 → 线程不能利用多核 → 计算密集用多进程、I/O 密集用多线程。
- ⚠️ **"GC回收机制："、"互斥锁：" —— 只有标题没有内容**。互斥锁是今天唯一的"高阶"内容，必须补：`Lock()` / `acquire()`（被占用则阻塞等待）/ `release()` / `locked()`；100 万次累加案例中 `num += 1` 非原子（读→加→写，中途切换丢计数），加锁后才是 200 万。
- ⚠️ **"rlock:重复锁" —— 标准叫法"可重入锁"**。用途对了一半：解决**同一线程嵌套获取同一把锁**。但"尽量使用rlock"和"性能不好"自相矛盾 —— 只有嵌套加锁才需要 RLock，普通互斥场景 Lock 更快。
- ⚠️ **线程部分没记 args/kwargs 传参**（和进程一样，线程也支持）；"线程的执行是无序的"没写原因（由 CPU 调度决定）。

> 📌 **补充发现**：GIL、死锁、RLock 这三点在课件《老师的笔记.md》书面内容里**没有**（课件只写了"线程缺点：不能使用多核"，没解释原因）。它们是你课上口头记下的扩展内容 —— 课堂扩展课件里查不到，笔记是唯一来源，务必自己写全，别只留个名词。
