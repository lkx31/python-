# 多任务编程 · 模糊知识点 / 易错点复盘

> 晚间复盘用：把掌握不牢固、容易混淆、容易出错的知识点列成清单。
> 用法：复习确认掌握后把 `- [ ]` 改成 `- [x]`；整节都掌握的可以删掉该节。
> 来源：老师课件《老师的笔记.md》重点与易错标注 + 2026-11-14 复盘新增（笔记 8 处写错/写不清 + 代码 4 个文件逐文件核对，见第四、五节）。

## 一、概念易混
- [ ] **并发 vs 并行** —— 并发=一段时间内交替执行（单核 CPU）；并行=真正同时执行（多核 CPU）。锚点是 CPU 核数
- [ ] **进程 vs 线程的调度单位** —— 进程=资源分配的最小单位；线程=程序执行（CPU 调度）的最小单位，别把"调度"安到进程头上
- [ ] **进程间不共享 vs 线程间共享全局变量** —— 进程：子进程=主进程资源的拷贝，各操作各的副本；线程：同一进程内共用一份
- [ ] **进程 vs 线程优缺点** —— 进程可用多核（绕 GIL）但开销大；线程开销小但不能用多核（GIL）

## 二、multiprocessing API 易错
- [ ] **模块名是 `multiprocessing`** —— 不是 multipart（那是课件拆词助记）
- [ ] **target 传函数名不带括号** —— `Process(target=study)` ✅ / `Process(target=study())` ❌（会先同步执行 60 秒再启动空进程）
- [ ] **args 单参数要逗号** —— `args=(3,)`；`(3)` 是 int 不是元组
- [ ] **kwargs 键必须与形参名一致** —— `kwargs={'count': 3}`
- [ ] **传参个数要和函数形参匹配** —— eat() 不接收参数就别传 args
- [ ] **main 保护** —— Windows 下进程创建/启动必须在 `if __name__ == '__main__':` 里
- [ ] **主进程默认等待子进程结束一并销毁** —— 代码不阻塞（"主进程执行完毕"先打印），但主进程退出前会等非守护子进程执行完
- [ ] **daemon=True 必须在 start() 之前设置** —— 主进程退出后守护子进程直接销毁
- [ ] **杀死子进程用 `进程.terminate()` / `进程.kill()`** —— 不是 `os.kill(pid, -9)`（-9 是 Linux 信号，Windows 没有）
- [ ] **join() 要在 start() 之后调用** —— `join([timeout])` 阻塞等待进程结束
- [ ] **current_process().pid / .name** —— 注意点号；主进程名 MainProcess、子进程 Process-1
- [ ] **os.getpid() vs os.getppid()** —— ppid = parent pid 父进程 id

## 三、threading API 易错
- [ ] **线程 target 同样不带括号** —— `Thread(target=study)`，别写 `study()`
- [ ] **线程 id 两种** —— `threading.current_thread().ident` / `.native_id`；`os.getpid()` 拿的是进程 id（同进程所有线程相同）
- [ ] **线程执行顺序无序** —— 由 CPU 调度决定
- [ ] **守护线程两种方式** —— `Thread(target=work, daemon=True)`（推荐）或 `setDaemon(True)`（弃用有警告）
- [ ] **主线程名 MainThread，子线程默认 Thread-1、Thread-2…** —— `__main__` 只是主程序脚本的模块名，和线程名没关系
- [ ] **GIL 全局解释器锁** —— CPython 同一时刻只允许一个线程执行 Python 字节码 → 线程不能用多核；I/O 等待时锁释放，所以线程适合 I/O 密集
- [ ] **`num += 1` 非原子操作** —— 读→加→写三步，中途切换丢计数，100 万次案例不加锁结果 < 200 万
- [ ] **互斥锁 Lock** —— `acquire()`（被占用则阻塞等待）/ `release()` / `locked()`；锁包住整个循环，不要放在循环里
- [ ] **死锁** —— 两个线程都在等对方资源，互相卡死
- [ ] **RLock 可重入锁** —— 同一线程可重复 acquire 同一把锁，解决嵌套加锁；比 Lock 慢，只有嵌套场景才用

## 四、代码复盘发现的问题（2026-11-14 新增，来源：我的代码 `代码/*.py`）
- [ ] **main 保护没包住创建/启动代码**（当日第二轮复盘新发现）—— 主进程和子进程、.py 只有 print 在 `if __name__=='__main__':` 里，Process 创建和 start() 都在外面 → Windows 下子进程重新导入模块时递归创建进程，报 RuntimeError；**整个「创建 + 启动」要挪进 if 里**
- [ ] **eat() 没形参却传了 args** —— 主进程和子进程、.py 的 `target=eat, args=('张三', 18)`，子进程一启动就 TypeError；要么给 eat 加形参，要么删掉 args
- [x] **target 括号 bug** —— 已修复（三个文件的 `target=study()` 都改成了 `target=study`，运行不再同步执行 60 秒）
- [x] **f-string 多余花括号** —— 已修复（主进程和子进程、.py 第 15 行末尾的 `}` 已删）
- [ ] **线程开太多** —— 多线程的执行顺序.py 开了 100 个线程（课件示例 10 个），验证无序结论没问题，但注意开销
- [ ] **无用 import / 注释里的旧 bug** —— 多线程的执行顺序.py 的 import multiprocessing、import os 没用；注释代码里还留着 target=study() 的错误写法，改完记得清掉
- [x] **进程.py / 线程.py 已是规范写法** —— target=函数名 + main 保护
